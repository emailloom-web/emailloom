Best Practices

WCAG Compliance Checklist

Accessibility best practices baked into every email that ships.

Semantic HTML with role="presentation" on layout tables
Logical heading hierarchy for screen readers
Meaningful alt text on every image
Minimum 4.5:1 color contrast for body text
Live text instead of text baked into images
Readable font sizes — 14px+ body copy
Descriptive link text, never "click here"
Language attribute set for assistive tech
Touch targets of 44px+ on mobile
No information conveyed by color alone
Logical reading order in the code

Coding Methods

Hybrid vs Responsive Email Coding

Watch how each approach reacts as the viewport changes — one snaps at a breakpoint, one flows the whole way.

@media (max-width:600px) { … }

Responsive

Media queries listen for the screen size and restyle the layout at defined breakpoints — columns stay side by side on desktop, then snap to stacked, full-width blocks the instant the viewport crosses the breakpoint. It gives pixel-level control over the mobile experience: font sizes, padding, image swaps, even hiding or reordering content.

  • Precise, per-breakpoint control of the mobile layout
  • Show, hide, or restyle elements just for small screens
  • Ideal for Apple Mail, Gmail apps & clients with media query support
max-width + fluid tables + MSO ghost tables

Hybrid (Fluid)

Hybrid coding doesn't wait for a breakpoint — layouts are built with fluid, percentage-based tables capped by max-width, so columns squeeze and stack naturally at any width. Conditional "ghost tables" keep Outlook's desktop clients locked to a fixed grid. No media queries required, so it works even where they're stripped or unsupported.

  • Adapts fluidly at every width — no breakpoint required
  • Renders correctly where media queries fail or get stripped
  • Ghost tables tame Outlook desktop (Word rendering engine)
EmailLoom ships both fluid-hybrid and responsive emails based on the requirement: choosing the best approach based on your requirements. Every email is built to render reliably across all major email clients, while leveraging responsive media queries wherever they're supported—combining maximum compatibility with an optimized user experience.
Testing & QA

Tested Before It Ever Hits an Inbox

Every build is previewed and QA'd in Litmus and Email on Acid across 90+ email clients and devices — nothing ships on hope.

Litmus

The industry-standard platform for email previews and pre-send QA. Every template is run through Litmus to verify rendering, links, and load performance across real client screenshots before a single send.

  • Instant previews across 90+ clients, devices & dark mode
  • Automated pre-send checklist — links, images, tracking & load speed
  • Spam & deliverability testing against major filters
  • Accessibility checks for screen readers and contrast

Email on Acid

A second, independent QA pass. Email on Acid's campaign pre-check catches client quirks Litmus can miss — especially across the many versions of Outlook — so edge cases are fixed before launch, not after.

  • Deep Outlook coverage — 2016, 2019, 365 & Windows Mail
  • Campaign Precheck: automated inbox display & content validation
  • Image validation, URL checks & UTM verification
  • Inbox display testing — subject line & preview text optimization

FAQ

Frequently Asked Questions

Quick answers about how EmailLoom works and what's supported.

Why custom-coded emails?
Custom-coded emails give complete control over rendering across every inbox — Outlook, Gmail, Apple Mail, Yahoo, and mobile. That means pixel-perfect layouts, true dark mode support, WCAG accessibility, and lighter, faster-loading code than any drag-and-drop builder can produce.
Do you support SFMC?
Yes — I'm a Salesforce Certified Marketing Cloud Email Specialist with deep, hands-on experience building emails with AMPscript, dynamic content, Content Builder templates, and Journey Builder automations for enterprise brands.
Do you support Klaviyo?
Absolutely. I build custom-coded Klaviyo templates and flows using Liquid templating — including dynamic product feeds, segmentation-driven content, and lifecycle campaigns for e-commerce brands like Cometeer, Gainful, and Fig.1 Beauty.
What other platforms and personalization languages do you work with?
Beyond SFMC and Klaviyo: Customer.io and Shopify (Liquid), Iterable and SendGrid (Handlebars), HubSpot (HubL), and more. If your ESP has a templating language, I can build modular, personalized emails in it.
Do you build accessible emails?
Yes — accessibility is built into every email I ship: semantic HTML structure, proper heading hierarchy, meaningful alt text, sufficient color contrast, and screen-reader-friendly markup that meets WCAG guidelines.
